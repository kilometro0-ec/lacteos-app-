Sin embargo, tengo que darte una respuesta directa y sin rodeos: No existe ninguna forma de usar mode: 'no-cors' en el navegador que funcione "siempre al 100%" para leer datos de un servidor externo. Vamos a derribar el mito de por qué no-cors no hace lo que la mayoría de la gente piensa, y te daré las soluciones reales que sí funcionan el 100% de las veces. El gran malentendido de mode: 'no-cors' Cuando pones mode: 'no-cors' en un fetch(), no estás saltándote la seguridad de CORS; al contrario, le estás diciendo al navegador: "Sé que este servidor no soporta CORS, así que no me dejes ver la respuesta". Lo que sí hace: Envía la petición al servidor y el servidor responde con un estatus 200 OK. Lo que NO hace: No te permite leer el contenido. El navegador bloquea la respuesta y te entrega una respuesta opaca (opaque response) con un status: 0 y el cuerpo vacío. La seguridad de CORS la ejecuta el navegador para proteger a los usuarios. Si pudieras saltártela con solo escribir no-cors, la seguridad de internet no existiría. Las 3 soluciones reales que funcionan al 100% Para obtener los datos de una API o servidor externo sin problemas de CORS, debes usar una de estas alternativas: 1. Modificar el Servidor (La solución correcta) Si tienes acceso al servidor que estás consultando (por ejemplo, si estás usando Node.js, Python, o incluso Google Apps Script), debes configurar los encabezados de respuesta para que permitan el acceso. Debes incluir este encabezado en la respuesta del servidor: HTTP Access-Control-Allow-Origin: * (O cambiar el * por el dominio específico de tu aplicación frontend para mayor seguridad). 2. Usar un Proxy CORS (Para desarrollo o APIs de terceros) Si el servidor no es tuyo y no puedes modificarlo, la solución estándar es enviar la petición a un servidor intermedio (Proxy). Dado que CORS es una regla que solo aplican los navegadores, un servidor backend puede consultar a otro servidor sin ninguna restricción. El proxy intermedia la petición, le agrega los encabezados CORS correctos y te devuelve los datos limpios. En desarrollo: Puedes usar servicios públicos como [https://cors-anywhere.herokuapp.com/](https://cors-anywhere.herokuapp.com/) (requiere activar un demo temporal). Ejemplo de código: JavaScript const proxyUrl = 'https://cors-anywhere.herokuapp.com/'; const targetUrl = 'https://api.tu-ejemplo.com/datos'; fetch(proxyUrl + targetUrl) .then(response => response.json()) .then(data => console.log(data)) .catch(error => console.error('Error:', error)); En producción: Lo ideal es que crees tu propio proxy (una función Serverless simple en Vercel, Netlify o Cloudflare Workers) para no depender de servicios de terceros. 3. Desactivar CORS en tu navegador (SOLO para pruebas locales) Si solo estás desarrollando en tu máquina y quieres probar cómo se ve tu frontend sin lidiar con CORS hoy, puedes abrir tu navegador con la seguridad desactivada.
